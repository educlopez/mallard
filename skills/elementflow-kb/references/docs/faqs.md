# FAQs

### 2. How to make all images in WebP

**PrestaShop 8 and PrestaShop 9** have a built-in WebP feature for product images, enabling all product, category, and brand images to be converted to WebP. If that's not enough, use the Element Flow WebP module to convert all images to WebP format.

**PrestaShop 1.7** users can use a WebP module to convert all images to WebP format.

The extension of product images may become `.webp` as expected, but other images may still show `.jpg` — don't worry, the server will serve them in WebP format if a WebP version exists.

### 4. Choose no extension or .jpg extension in the file manager

Once you generate **WebP images** for the `/img/cms/` folder using a WebP module, the same image will show twice in the file manager — one with no extension, one with `.jpg` extension. **Choose the one with NO extension** — its `.jpg` extension just isn't shown by the file manager. The one showing `.jpg` actually has a `.jpg.webp` extension.

If the `.webp` one gets chosen instead, the image will show fine everywhere except in the **Safari** browser.

### 5. How to add custom icons

Download icons from icomoon.io and upload the zip file to your site in the "Upload custom icons" section on BO > Element Flow > Settings. The process takes only a few minutes; both SVG and font icons will be added.

### 6. How to add custom fonts

Go to BO > Element Flow > Settings > "Upload custom fonts" section to upload custom fonts.

### 9. What does the "Clear template && css cache" button do?

The Clear cache button on BO > Improve > Element Flow > Settings is used to clear template files generated by Element Flow. The content of a record is saved to a template file, and PrestaShop loads that template to show content on the front end. The template file updates automatically when content changes, but in two cases it needs to be erased manually for regeneration:

1. When Element Flow is upgraded.
2. When a file included in the template changes — e.g. when a product miniature changes, all template files using that miniature need to be erased to regenerate.

### 10. How to completely clear the caches

Do the following steps (**order matters**):

1. Go to BO > Advanced Parameters > Performance > **Enable** CCC for js and css, to avoid browser cache issues.
2. Go to BO > Improve > Element Flow > Settings page > **Clear the template & css cache** (see FAQ #9 above).
3. Use an FTP client to remove `/var/cache/dev/FrontContainer.php` and `/var/cache/prod/FrontContainer.php`. Only needed once after every update.
4. Go to BO > Advanced Parameters > Performance > click **Clear cache** in the top right to clear the Smarty cache.

If an issue still exists after clearing caches completely this way, it's not a cache-related issue.

Notes:

1. No need to clear the **browser** cache.
2. The **Template compilation** and **Cache** settings on BO > Advanced Parameters > Performance don't matter for this process.

### 11. What's the Smarty cache setting?

The **Smarty cache** setting on the Performance page must be enabled for the Smarty cache setting on every record to work. If the overall Smarty cache is disabled, all records won't be cached even if their individual Smarty cache is enabled.

If Smarty cache for a record is **enabled**, its content will be cached — this is an excellent way to shorten page load time. Recommended: **enable Smarty cache for all records except theme templates** (theme templates live under BO > Element Flow > Theme builder > Theme templates).

If Smarty cache is **disabled**, PrestaShop queries the database to regenerate content every time the record is shown — useful in some cases, e.g. to highlight the current category in the menu.

Some widgets update automatically even in a cache-enabled record, like the shopping cart widget, because their content shouldn't be cached — it updates automatically via Ajax.

Why should Smarty cache be **disabled for theme templates** (product templates, category templates)? Whether enabled or not, the template works fine because:

1. PrestaShop retrieves data from the database every time for every category page regardless of the Smarty cache setting, so enabling it won't speed up page load.
2. The product list of a category cached on first template use only works for that category — it gets automatically updated via Ajax on other categories when loaded, which slows the page rather than speeding it up.

Every time a record is edited, Element Flow tries to clear its cache, but whether it succeeds depends on the **Template compilation** setting on the Performance page.

For compatibility with other cache modules: enable Smarty cache for all records except theme templates, as always.

### 12. How to perfectly center an element vertically and horizontally

1. Set the parent's position to Relative (containers are Relative by default, so usually nothing to do here).
2. Set a **fixed width** on the element.
3. Set the element's **Position: Absolute, Top: 50%, Left: 50%**.
4. Set **Offset X** and **Offset Y** to **-50%** in the **Transform** section.

### 13. Clicking "Add to wishlist" does nothing

The wishlist module adds code to the footer, which is crucial for it to function. If "Add to wishlist" buttons don't work, it's most likely because the wishlist module was removed from the `displayFooter` hook — transplanting it back fixes the issue.

### 14. The editor doesn't load on a multistore site

This happens when different stores use different domains, e.g.:

- First store: `one.elementflow.com`
- Second store: `two.elementflow.com`

If logged in to the first store via `one.elementflow.com/youradminfolder`, you **can't** edit content on the second store, because it triggers a cross-domain violation. To edit content on the second store, log in to its back office using `two.elementflow.com/yourbackofficefolder`.

The public demos use the same domain (e.g. `elementflow.com/one/` and `elementflow.com/two/`), so once logged in you can edit content on every demo site.

### 15. Can I have a dev site?

It's common practice to have a dev site. You can install Element Flow on both the live site and the dev site. Put the dev site under maintenance mode to make sure Element Flow works fine without needing to register. If the dev site is a copy of the live site, you may get a notice saying the domain doesn't match — just ignore it.
